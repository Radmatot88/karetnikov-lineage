### 1.1. Архитектура и состав репозитория (85 файлов)
Репозиторий представляет собой эталонный генеалогический Agent Skill (`Codex` / `Claude Code` / `Antigravity`) для расследования родословных на территории бывшего СССР и Российской империи, построенный на принципе **Evidence-First (доказательства прежде выводов)** и полной автономии.

#### А. Исполняемые Python-скрипты (`scripts/` — чистая стандартная библиотека Python 3 + Pillow):
1. **`scripts/gwar.py` (`17 464 байт`) + `scripts/ca/russian_trusted_root_ca.pem` / `russian_trusted_sub_ca.pem`** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - Прямой read-only API-клиент к порталу Первой мировой войны **`https://gwar.mil.ru`**.
   - Подключает корневой и промежуточный сертификаты Минцифры РФ (`Russian Trusted Root CA` и `Sub CA`) изолированно к `ssl.SSLContext` без модификации системного хранилища Windows и без отключения проверки TLS!
   - Бьет напрямую в JSON-эндпоинт `POST https://gwar.mil.ru/gt_data/?builder=Heroes` по 4 сущностям (`chelovek_donesenie`, `chelovek_gospital`, `chelovek_nagrazhdenie`, `chelovek_plen` — картотека военнопленных РГВИА).
   - Поддерживает 4 режима CLI:
     - `search` — поиск по `--surname`, `--given`, `--patronymic`, `--birth-place`, `--gubernia`, `--event-place`, `--regiment`;
     - `volost` — выгрузка всех карточек конкретной волости и губернии (`birth_place_volost`, `birth_place_gubernia`) с поддержкой докачки через checkpoint-файл (`--out`);
     - `places` — **оффлайн-алгоритм дешифровки искаженных писарями названий сел**: группирует все карточки по `(gubernia, uezd, volost)`, отбрасывает префиксы (`с.`, `д.`, `хутор`, `слобода`) и считает сходство (`similarity`) одновременно по полному слову и по **согласному скелету** (`re.sub(r"[аеиоуыэюяіїєйăâîьъ]", "", value)`) через `difflib.SequenceMatcher`;
     - `page` — по `documents_pages.pages_id` запрашивает `POST /gt_data/?builder=HeroesStranitsa`, парсит XML-разметку `obraz_s_oblastyami` и возвращает прямой URL скана (`https://gwar.mil.ru/cdn/imagesfww/...`) и точные координаты строк (`zones`) на архивном листе!
2. **`scripts/scan_montage.py` (`8 414 байт`)** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - Конвейер скоростного визуального чтения сотен неиндексированных сканов метрических книг, ревизских сказок и подворных карточек Переписи 1917 года.
   - Принимает папку кадров, обрезает половину разворота (`--half left|right|auto`), поворачивает (`--rotate`), вырезает целевую графу (например, только столбец «Родители» в метрической книге или строку «Фамилия, имя и отчество домохозяина» в карточке переписи 1917 г. по относительным координатам `--box x0,y0,x1,y1`), усиливает контраст (`--contrast 1.4`) и склеивает по 12–24 полосы на один вертикальный лист с номером кадра слева.
   - Позволяет просмотреть 500 листов метрической книги за 5 минут вместо поштучного открытия каждого кадра!
3. **`scripts/audit_evidence.py` (`22 268 байт`)** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - Строгий валидатор ссылочной целостности и анти-галлюцинационный линтер для 4 CSV-реестров (`person-register.csv`, `artifact-register.csv`, `claims-register.csv`, `relationship-register.csv`), журнала `search-log.csv` и текста `final-report.md`.
   - Проверяет **группы независимости (`independence_group`)**: запрещает присваивать статус `corroborated` или `strongly-corroborated`, если два документа восходят к одному первоисточнику (например, метрическая запись, её индекс на FamilySearch/Яндексе и скопировавшее их дерево считаются одной группой `PARISH-BOOK-1902-ACT17`, а не тремя подтверждениями!).
   - Проверяет, что каждый упомянутый в отчете ID (`P-0001`, `A-0001`, `C-0001`, `R-0001`) реально существует в CSV, а его статус в тексте отчета совпадает с реестром.
4. **`scripts/familysearch.py` (`3 433 байт`) + `scripts/familysearch_browser.py` (`7 027 байт`)** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - Локальный анализатор сохраненных браузерных JSON-фрагментов индекса FamilySearch (`/ark:/61903/1:1:...` и `/ark:/61903/3:1:...`) с регулярными выражениями по двум слоям: `--surnames` (целевые фамилии) и `--beacons` (маяки: редкие имена восприемников, соседей, приписных деревень).
5. **`scripts/register_search.py` (`18 762 байт`) + `scripts/research_common.py` (`7 541 байт`) + `scripts/init_case.py` + `scripts/hash_artifact.py` + `scripts/build_pdf.py`** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - Атомарная регистрация находок из GWAR, FamilySearch или ручных JSON-выгрузок (`source: "manual"`) в реестр артефактов с вычислением `SHA-256`, дедупликацией по `snapshot_key` и защитой от гонок записи через файл блокировки `state_lock`.

### 2.2. Скрипты, API и поисковые особенности гражданских и региональных баз (`yandex.ru/archive`, `openlist.wiki`, `rgada.sovadev.pro`, АИС архивов)

### 4.2. Библиотеки дедупликации персон и нечеткого сопоставления (`Fuzzy Matching`) дореволюционной орфографии и топонимов

В архивах XVIII–XX вв. одна и та же семья и одно и то же село записываются десятками способов:
- *Куманинъ / Куманин / Команин*; *Зубковъ / Зубков / Зупков*; *Юхинъ / Юхин / Ехин*; *Каретниковъ / Коретников*;
- *Егоръ Петровъ / Георгій Петровичъ / Юрій Петровъ*; *Евдокія / Авдотья*; *Іоаннъ / Иванъ*;
- *с. Новый Шуструй / с. Никольское, Новый Шуструй тож / д. Шуструй*; *Плешаново / Ново-Самарское*.

Для автоматической сшивки (`Cross-Matching`) этих записей без ложных слияний однофамильцев используется четырехслойный стек:

1. **Вероятностная сшивка записей (`Probabilistic Record Linkage`): `Splink` и `dedupe`** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - **`Splink` (`moj-analytical-services/splink`)**: `https://github.com/moj-analytical-services/splink` (`pip install splink`) — сверхбыстрый движок вероятностного связывания записей по модели Феллеги-Сантера (Fellegi-Sunter) поверх `DuckDB`. Умеет взвешивать совпадение `(Фамилия + Имя + Отчество + Год рождения ±3 года + Село + Имя отца/матери)` даже при пропущенных полях!
   - **`dedupe` (`dedupeio/dedupe`)**: `https://github.com/dedupeio/dedupe` (`pip install dedupe`) — библиотека активного обучения для дедупликации карточек персон.
2. **Скоростное нечеткое сравнение строк: `RapidFuzz`** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - **URL:** `https://github.com/rapidfuzz/RapidFuzz` (`pip install rapidfuzz`)
   - Написанная на C++ библиотека для метрик Дамерау-Левенштейна и Джаро-Винклера (`fuzz.WRatio`, `distance.JaroWinkler`).
3. **Русская морфология, лемматизация и падежи ФИО: `Natasha` + `pymorphy3` + `Petrovich`** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - **`natasha/natasha`** (`https://github.com/natasha/natasha`) — извлечение ФИО (`NamesExtractor`) и адресов (`AddrExtractor`) из сплошного OCR-текста описей и метрик;
   - **`pymorphy3`** (`https://github.com/no-plagiarism/pymorphy3`) — приведение косвенных падежей из метрических записей (*«у крестьянина Егора Петрова Куманина»* -> *«Егор Петров Куманин»*) к именительному падежу;
   - **`damirazo/Petrovich`** (`https://github.com/damirazo/Petrovich`) — генерация всех падежных форм фамилии/имени/отчества для полнотекстового поиска по дореволюционным документам и описям РГАДА.
4. **Алгоритм дореволюционной фонетической нормализации и согласного скелета (из `gwar.py` + `ex-ussr-locale-guide.md`)** `[⚙️ OPEN_SOURCE / TECH_ASSET]`:
   - Перед вызовом `RapidFuzz` / `SequenceMatcher` применяется детерминированный препроцессор:
     1) **Транслитерация старой орфографии (до 1918 г.):** `ѣ -> е`, `і -> и`, `ѳ -> ф`, `ѵ -> и`, удаление краевого `ъ`, замена `ё -> е`;
     2) **Нормализация патронимов и церковных имен по словарю эквивалентов (как поисковых гипотез):** `Іоанн/Иван`, `Георгий/Егор/Юрий`, `Евдокия/Авдотья`, `Параскева/Прасковья`, `Косма/Кузьма`, `Димитрий/Дмитрий`, а также приведение полуотчеств (`Петров сын` / `Петров` <-> `Петрович`);
     3) **Согласный остов (Consonant Skeleton) для топонимов и фамилий:** удаление всех гласных и разделителей (`re.sub(r"[аеиоуыэюяіїєйьъ]", "", s)`) — благодаря этому *«Коретниковъ»* и *«Каретников»* дают единый скелет **`кртнкв` (`1.00`)**, а *«Зубковъ»* и *«Зупков»* (при оглушении звонких `б->п`, `в->ф`, `г->к`, `д->т`, `ж->ш`, `з->с`) — единый фонетический ключ **`зпкф` (`1.00`)**!
