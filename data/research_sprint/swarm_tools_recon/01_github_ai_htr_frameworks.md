## 📌 РЕЗЮМЕ ОПЕРАТИВНОЙ ОБСТАНОВКИ (BLUF)

1. **Парсинг архивов РФ (2024–2026):**
   - Прямого открытого REST API у большинства российских архивных порталов (`ya.ru/archive`, `pamyat-naroda.ru`, `cgaso.regsamarh.ru`) нет — сервисы защищены WAF, Cloudflare или Яндекс SmartCaptcha.
   - Однако сообществом созданы специализированные расширения и CLI: **`marydruzina/yandex-archive-downloader`** и **`Aoneti/Regional-Archive-Downloader`** для выгрузки сканов из «Поиска по архивам» и региональных АИС; **`dmalch/go-familio`** для обратного инжиниринга API v2 Familio; консольный **`okolobaxa/rgada-downloader`** для выкачивания описей РГАДА; а для базы Первой мировой войны (`gwar.mil.ru`) существует прямой JSON-клиент **`gwar.py`** (из фреймворка `ex-ussr-kinship-research`), работающий с бэкендом через национальные сертификаты Минцифры.
   - База жертв репрессий **`ru.openlist.wiki`** работает на нативном движке MediaWiki и предоставляет полнофункциональный открытый API (`/api.php`) для автоматического сбора структурированных анкет.

2. **Нейросети распознавания скорописи (HTR / OCR):**
   - **Яндекс «Поиск по архивам»:** совершил технологический скачок — в мае 2026 года внедрена мультимодальная модель **Alice AI VLM**, которая не просто читает скоропись и дореформенный текст с точностью 90.5% по ФИО, но и автоматически строит граф ролей метрической книги («родившийся» – «отец» – «мать» – «восприемник», «жених» – «невеста» – «поручители»).
   - **Локальный и Open-Source HTR:**
     - **`Manuscript OCR` (`konstantinkozhin/manuscript-ocr`)** — готовый открытый Python-пайплайн (`pip install manuscript-ocr`) на базе ONNX Runtime / PyTorch, заточенный под российские архивные рукописи XVIII–XIX вв., старую орфографию и титла.
     - **`Digital Peter` (Сбер / `ai-forever`)** — открытые веса и датасет (`ai-forever/ReadingPipeline-Peter` на HuggingFace) для сверхсложной скорописи петровской эпохи (XVII–XVIII вв.).
     - **`Kraken` + `eScriptorium`** — открытый европейский self-hosted стек с публичными моделями на Zenodo для старославянского унциала, полуунциала и скорописи (*PP-OCRv6 for Kraken*, модели Ахима Рабуса).
     - **`Transkribus`** — признанный мировой лидер, содержащий публичные модели *Russian Generic Handwriting 2* (CER ~5.8%), *Russian Generic Handwritten and Typed 1* и *Generic Church Slavonic Handwriting 3* (CER ~3.29%), но сдерживаемый облачной платной кредитной моделью.

3. **Графы, валидация GEDCOM и AI-агенты:**
   - Для Python-разработки золотым стандартом стали **`gedcom7`** (строгая валидация по ABNF спецификации GEDCOM 7.0 с детектором висячих ссылок) и **`ged4py`** (максимально отказоустойчивый парсинг любых диалектов GEDCOM 5.5.1 с поддержкой кодировок ANSEL/UTF-8).
   - Появились специализированные **MCP-серверы (Model Context Protocol)** для подключения AI-агентов напрямую к генеалогическим базам: **`JonathanReiss15/familysearch-mcp`** (авторизация через локальный браузер, обход дерева до 8 поколений) и **`igormel81/genealogy-mcp`** (аудит доказательств и поддержка 79 источников).
   - Для веб-визуализации деревьев в браузере лучшим легковесным решением является **`PeWu/topola-viewer`** (TypeScript + D3.js), способный рендерить интерактивные древа предков и родственников напрямую из GEDCOM без тяжелых бэкендов.

## 2. AI, HTR И OCR ТЕХНОЛОГИИ ДЛЯ ЧТЕНИЯ СКОРОПИСИ XVII–XIX ВВ. И МЕТРИК

### 2.1. Мировой эталон: Платформа Transkribus (READ-COOP)

Transkribus — ведущая платформа для распознавания рукописных архивных текстов (HTR). В публичном хабе моделей доступны следующие профильные модели для русского языка и скорописи:

1. **`Generic Church Slavonic Handwriting 3`:**
   - **Авторы:** Проф. Ахим Рабус (Achim Rabus) и Елена Ренье (Фрайбургский университет, проект QuantiSlav).
   - **Область:** Рукописный церковнославянский язык восточнославянского извода (унциал, полуунциал, ранняя скоропись X–XVI вв.). Обучена на корпусах Супрасльской рукописи, Огласительных поучений Кирилла Иерусалимского, Великих Миней Четьих.
   - **Точность:** Выдающийся показатель CER (Character Error Rate) ~ **3.29%**.
2. **`Russian Generic Handwriting 2`:**
   - **Авторы:** Проект MultiHTR (Фрайбургский университет, Эстонский госархив, проект «Прожито», INEL Гамбург).
   - **Область:** Разнообразные российские почерки конца XIX — начала XX века (мемуары, письма, дневники, архивные дела).
   - **Точность:** CER ~ **5.8%**. Служит базовой моделью для трансферного дообучения под конкретные архивные фонды.
3. **`Russian Generic Handwritten and Typed 1`:**
   - **Автор:** Алексей Тихонов.
   - **Область:** Смешанные рукописные и машинописные материалы XVIII–XX вв., включая дореволюционные следственные дела и документы общества «Мемориал».
4. **Узкоспециализированные модели:** `Ostromir v1.0` (Остромирово евангелие XI в.), `Macarius 1.0` (старопечатная кириллица XVI в.), `Russian-RychkovArchive-v1.0` (архивные документы дореформенной орфографии).
5. **Ограничения Transkribus:** Проприетарная облачная инфраструктура, расход кредитов (Transkribus Credits) за каждую обработанную страницу, невозможность автономного запуска модели на изолированном сервере без подключения к серверам READ-COOP.

### 2.2. Открытая self-hosted альтернатива: `Kraken` и `eScriptorium`

Франко-европейский стек с открытым исходным кодом для независимого распознавания рукописей на локальных GPU без передачи данных во внешние облака:

- **`Kraken` (`kraken.re`, `pip install "kraken>=7.1.0"`):**
  - Движок HTR/OCR, поддерживающий распознавание текстов произвольного направления и сложной верстки.
  - Поддерживает веса моделей в форматах `.mlmodel` и современных `.safetensors`.
- **`eScriptorium` (`escriptorium.eu`):**
  - Веб-платформа с открытым исходным кодом (Django, Celery, Vue) для разметки, сегментации страниц, транскрипции и инференса моделей Kraken.
- **Публичные модели на Zenodo и HuggingFace:**
  - **`PP-OCRv6 for Kraken` (HuggingFace: `small-models-for-glam`):** Мультиязычная базовая модель с поддержкой современного и исторического кириллического письма.
  - **`Generic HTR model for Old Cyrillic uncial and semi-uncial script styles (11th-16th c.)` (Zenodo):** Модель Ахима Рабуса и Даниэля Штёкля Бен Эзры для древнерусской и старославянской книжности.
  - **Базовые модели сегментации строк (Layout Analysis):** Модели **`Orli Base Model`** и **`BLLA`** (на Zenodo), автоматически выделяющие базовые линии (baselines) и полигоны строк даже при сильном пересечении выносных элементов букв в скорописи.

### 2.3. Отечественные AI-разработки для скорописи XVII–XIX вв.

#### А. Проект «Цифровой Петр» (Digital Peter / Sber AI / ai-forever)
- **Репозитории:**
  - `https://github.com/ai-forever/digital_peter_aij2020`
  - `https://github.com/ai-forever/ReadingPipeline`
- **Датасет и веса на HuggingFace:**
  - Датасет: `https://huggingface.co/datasets/ai-forever/Peter` (свыше 265 000 размеченных символов скорописи рубежа XVII–XVIII веков, полигональная разметка строк в COCO-формате).
  - Веса: `https://huggingface.co/models/ai-forever/ReadingPipeline-Peter` (готовые PyTorch и ONNX веса OCR-модели и детектора строк).
- **Практическое значение:** Единственная в мире открытая нейросеть промышленного уровня, обученная на экстремально сложной скорописи рубежа XVII–XVIII веков (почерк Петра I и синхронных приказных дьяков). Служит отличным базовым энкодером для столбцов РГАДА Ф. 210.

#### Б. Фреймворк `Manuscript OCR` (`konstantinkozhin/manuscript-ocr`)
- **Установка:** `pip install manuscript-ocr` (доступен на PyPI и GitVerse).
- **Архитектура:** Полноценный конвейер предобработки, сегментации строк и транскрипции на базе PyTorch и ONNX Runtime.
- **Поддерживаемое железо:** CPU (с SIMD-оптимизацией), GPU (NVIDIA CUDA) и Apple Silicon (CoreML).
- **Особенности:** Специально оптимизирован для российских рукописей XVIII–XIX веков (ревизских сказок, метрических книг, рекрутских списков). Поддерживает буквы, исключенные реформой 1918 года (ѣ, ѳ, і, ѵ), титла и выносные согласные.

### 2.4. Технологический скачок Яндекса: от OCR к Alice AI VLM (2023 ➔ 2026)

В мае 2026 года команда сервиса «Яндекс Поиск по архивам» опубликовала фундаментальный отчет о переводе платформы на мультимодальную модель **Alice AI VLM** (Vision-Language Model):

1. **Отказ от классического двустадийного конвейера (OCR ➔ NER):**
   - Раньше система сначала распознавала изолированные строки (OCR), а затем пыталась найти регулярными выражениями или BERT-моделями имена и даты. На табличных структурах метрических книг это приводило к срывам столбцов.
2. **Семантическое понимание метрических книг:**
   - Новая VLM-модель обрабатывает весь разворот метрической книги целиком, понимая пространственные связи между столбцами.
   - Модель на лету строит граф родства для каждой актовой записи:
     - Раздел о рождении: классифицирует сущности **«родившийся»**, **«отец»**, **«мать»**, **«восприемники (крестные)»** с их сословием и деревней приписки.
     - Раздел о браке: связывает роли **«жених»**, **«невеста»**, **«поручители по жениху»**, **«поручители по невесте»**.
     - Раздел об умерших: связывает **«умерший»**, **«причина смерти»**, **«возраст»**, **«совершавший погребение причт»**.
3. **Точность:** Точность семантического извлечения полных связок ФИО достигла **90.5%**, что сделало сервис de facto главным агрегатором архивных знаний в РФ для регионов, передавших фонды (включая Оренбургскую область — ОГАОО).

1. **Хронологические аномалии:**
   - Ребенок родился позже даты смерти матери (или более чем через 9 месяцев после смерти отца).
   - Возраст матери при рождении ребенка менее 13 или более 55 лет.
   - Возраст вступления в брак менее 15 лет (для мужчин) / 13 лет (для женщин по законам РИ) или более 90 лет.
   - Продолжительность жизни превышает 115 лет (требует обязательной проверки на совмещение двух полных тезок — деда и внука).
2. **Топологические и графовые аномалии:**
   - Наличие циклов в ориентированном ациклическом графе (DAG) родства.
   - Несимметричные связи: родитель указывает ребенка в `CHIL`, но у ребенка в `FAMC` указана другая семья.
   - Дублирование первичных ключей (`@I0001@`).
3. **Эпистемические аномалии доказательств (Genealogical Proof Standard):**
   - Утверждение о родстве помечено как доказанное (`CONFIRMED_DOC` / `CORROBORATED`), но в поле источника отсутствует точный архивный шифр (Архив, Фонд, Опись, Дело, Лист/Скан).
   - Использование одного составного источника (например, поздней советской справки с пересказом метрики) под видом двух независимых подтверждений.

### 3.3. Специализированные платформы: Gramps, Gramps Web и GeneWeb

1. **Gramps Desktop & Gramps Web (`grampsweb.org`):**
   - **Data Verify Tool:** Встроенный инструмент верификации данных сканирует базу на 28 типов ошибок (хронология, пустые события, некорректные связи). В Gramps Web эти проверки выполняются в фоновом режиме через Celery/Redis.
   - **FAN-club анализ (Friends, Associates, Neighbors):** Gramps поддерживает нативный механизм ассоциаций (*Associations*), позволяя привязывать к событиям поручителей, свидетелей, крестных и соседей с указанием их конкретной роли без искажения кровного древа.
   - **Интерактивные графы:** Модуль *Graph View* строит динамические сетевые диаграммы родственных связей.
2. **GeneWeb (`github.com/geneweb/geneweb`):**
   - Написан на OCaml гениальным французским математиком Даниэлем де Роглодром (создателем Caml/OCaml).
   - Содержит быстрейшие в мире алгоритмы расчета степеней родства, кровного родства (consanguinity) и инбридинга для баз данных на сотни тысяч персон. Идеален для глубокого анализа однодворческих и переселенческих сел со множественными перекрестными браками.

### 3.4. Визуализация графов в веб: Topola Viewer, Cytoscape.js, vis-network

1. **Topola Viewer & Core Library (`PeWu/topola-viewer`, `PeWu/topola`):**
   - **Стек:** TypeScript, D3.js.
   - **Назначение:** Специализированный открытый компонент для рендеринга генеалогических деревьев. Поддерживает режимы: «Предки» (Hourglass / Pedigree), «Потомки», «Все родственники».
   - **Преимущество:** Умеет парсить файлы `.ged` на клиенте без передачи на сервер, строит идеальные ортогональные линии связей без наложения узлов. Идеально интегрируется в Astro/HTML фронтенд.
2. **Cytoscape.js (`cytoscape.org`):**
   - Мощнейший JavaScript-движок теории графов. Позволяет отображать сложные кластерные сети переселенцев, прихожан и торговых связей купечества с физической симуляцией раскладки (Dagre, CoSE-Bilkent, Cola).
3. **vis-network (`visjs.github.io/vis-network`):**
   - Легковесная библиотека canvas-графов. Отлично подходит для интерактивных карт локального сообщества (FAN-club networks).
